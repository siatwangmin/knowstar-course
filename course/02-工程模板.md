# 2｜认识工程与固定技术路线

环境 Skill 已在空目录生成**真实可运行的基础工程** `knowstar-learning/`：React 页面、TypeScript 配置、Vite 构建、Ionic 和 Capacitor 依赖、CloudBase SDK、Tailwind 3/PostCSS/Autoprefixer 的本地构建配置、锁文件、环境变量样例。它只显示占位页，不含教师的怪兽卡业务代码。你继续修改它，不复制教师工程，也不运行 `npm install`。

## 只做这两件事

1. 在 TraeWork 中打开 `knowstar-learning/`。导入[课程 Skill ZIP](../knowstar-course-skill.zip)。
2. 发给 TraeWork。课程还提供[工程约束模板](../templates/AGENTS.course.md)和[工程说明模板](../templates/README.course.md)，让它更新学员工程里的 `AGENTS.md`、`README.md` 和占位页的下一步提示，以后每阶段都会读到固定路线：

```text
请使用 knowstar-course Skill 检查当前空白工程，告诉我它能做什么、还没有什么。读取课程 Skill 内的 templates/AGENTS.course.md 和 templates/README.course.md，更新本工程 AGENTS.md、README.md，并将 src/App.tsx 占位页的下一步提示改为只需 docs/design/PRD.md 和 Canvas 导出的 HTML；旧镜像里出现的 spec、交接包或无登录说明不适用于本课程。固定技术路线与 Docker Compose 命令；不能让我挑框架、数据库、安卓打包器或 AI 服务商。请检查 package.json、package-lock.json、tailwind.config.js、postcss.config.js、src/style.css 的 @tailwind 指令、.env.example 和容器中的 Web 构建；现在不要编写产品功能。
```

**过关检查**：TraeWork 确认这只是技术底座，Tailwind/PostCSS/Autoprefixer 已在容器本地安装，且 `docker compose exec app npm run build` 成功。如果找不到工程目录或依赖，回到第 1 步。

## 技术路线由课程决定

| 你说的版本 | TraeWork 默认采用 | 你无需选择的内容 |
| --- | --- | --- |
| 本地网页 V1 | Ionic React + TypeScript + Vite + Tailwind 3 本地编译；IndexedDB 保存本机数据；预留 Repository 接口 | React 与其他框架、云服务、APK、AI 模型 |
| 云端 V2 | 同一个网页；CloudBase PostgreSQL + 课程演示用户的数据和图片；GitHub Pages 托管**静态网页** | 数据库和前端托管平台的候选清单 |
| 安卓 V3 | 同一代码的 Capacitor 6 APK；沿用 V2 演示用户登录及云端同步 | 重写原生 App、另选同步服务 |
| AI V4 | CloudBase 云函数调用**硅基流动 API**；默认 Qwen/Qwen3.8-27B 识题、deepseek-ai/DeepSeek-V4-Flash 做文本学习；Key 只在服务端 | CloudBase 自带 AI 或其他模型服务商的比较 |

**两个地址的区别**：GitHub Pages 放大家能打开的网页文件；CloudBase 管演示用户的错题、图片和云函数。同一学员在网页和 APK 登录同一个课程演示用户后共享数据；只使用虚构例题。`VITE_*` 配置会被打进网页，只能放公开配置；演示用户密码、硅基流动 Key、管理密钥绝不能放进去。

从 V1 就保持同一套页面和数据字段，V2 只增加云端数据实现，V3 复用网页打 APK，V4 只增加 AI 能力。下一步先去[做需求与原型](03-需求与原型.md)。
