# 6｜V3：把同一个网页做成安卓 APK

你只需说“我要安卓版本”。继续使用 V2 工程和课程演示用户；手机首次打开时手动登录一次，与网页使用同一账号。

```text
使用 knowstar-course Skill 做 V3。先检查 V2 的两个浏览器以同一演示用户登录后已共享题目和图片。沿用 Ionic React、Capacitor 6 和当前 Canvas 页面，用统一容器生成并编译 Android debug APK；不要在宿主机下载 npm、Capacitor 或 Gradle 依赖。构建前确认 Android 使用 VITE_DATA_MODE=cloudbase，并将最新网页同步进原生工程。登录表单与 getSession() 恢复逻辑随 Web 构建进入 APK；不把演示用户密码预置进 APK。完成后给我 Windows 下 APK 的绝对路径、SHA-256 和真机检查步骤。
```

TraeWork 在课程目录运行 `docker compose run --rm app knowstar-android-build`。该命令生成 Android 工程、编译网页、同步资源，再使用镜像中的 Gradle/Android 依赖构建 APK。APK 位于 `knowstar-learning/android/app/build/outputs/apk/debug/app-debug.apk`。单独执行 `./gradlew assembleDebug` 不会更新网页资源。课堂验收使用 debug APK；正式上架需要另外签名。

| 在手机上操作 | 预期结果 |
| --- | --- |
| 安装并打开 APK，输入与网页相同的演示用户凭据 | 登录成功后显示网页已有的示例错题；重开可恢复会话 |
| 手机新增题目和手绘图，网页刷新 | 网页显示同一题和图片 |
| 网页升级或删除题目，手机点“刷新同步” | 手机显示变化 |
| 退出登录或输入错误密码 | 无法访问云端数据，提示明确 |
| 翻牌、触摸画板、长题干、软键盘、返回键 | 交互可用，内容不被遮挡 |
| 断网后提交 | 提示失败并保留输入，不假称已同步 |

手机必须能访问 CloudBase；若请求失败，让 TraeWork 检查 WebView 网络、CloudBase 来源配置与会话。课程不要求原生 Camera 插件。

**过关检查**：APK 编译、安装和启动成功；手机与网页用同一演示用户双向同步；退出与断网提示可见。把设备型号、Android 版本、APK 摘要、截图和问题写到 `docs/progress/V3.md`，再进入[V4](07-V4-AI.md)。
