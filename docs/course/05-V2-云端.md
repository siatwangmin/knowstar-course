# 5｜V2：用同一个课程演示用户同步云端数据

你只需说“我要部署云端”。V1 的 IndexedDB 本地版保留；V2 切换到在线 CloudBase PostgreSQL。每位学员在**自己的 CloudBase 环境**创建一个课程演示用户；同一学员的网页和 APK 各登录一次，之后共享该用户的数据。不做注册、账号切换、多用户管理。只录虚构例题，不录真实学生信息。GitHub Pages 的静态发布配置可先做好；公网测试可以后补。

## 第一步：开通 CloudBase 并建立演示用户

先检查[环境配置阶段](01-环境.md)准备的 CloudBase 清单；尚未开通时按[CloudBase 开通步骤](10-开通CloudBase.md)创建你自己的 PostgreSQL 环境，记下 EnvId 和浏览器 Publishable Key。把下面提示词发给 TraeWork：

```text
使用 knowstar-course Skill 做 V2。先读取 https://docs.cloudbase.net/skill.md 并完成官方 Skill/MCP 接入，核对我的 EnvId、地域、PostgreSQL、PG Storage、Publishable Key 和 usernamePassword 登录方式。阅读我自己的 V1 工程、PRD.md 和 Canvas HTML；不要要求额外的 spec。请列出要创建的 demo_* 表、图片桶、权限和一个课程演示用户的清单。由我在 CloudBase 控制台或安全的管理流程中设置演示用户的账号与随机密码；不要在聊天、Git、VITE_*、网页代码或 APK 中写密码，也不要自动注册访客。每项资源创建后报告实际结果。
```

**你要做**：在自己的 CloudBase 环境创建一个用户名密码用户，自己保管凭据；不要使用教师账号，也不要把密码发给 TraeWork。**预期结果**：TraeWork 确认环境可访问，依据**当前前端实际读写的表名**列出所需表和图片桶；`demo_questions` 等只是命名示例，若工程已经读写 `wrong_questions`，必须检查并迁移 `wrong_questions`。资源依据 PRD 的业务字段与现有代码写成版本化 SQL 迁移并执行，不要求学员先写 spec。为浏览器实际读写的每张表配置 `authenticated` 权限与 SELECT/INSERT/UPDATE/DELETE RLS；用户归属字段（如 `user_id`）用 `auth.uid()` 绑定演示用户，写入时不得固定为 `null`。图片桶也只允许已登录用户读写。不要开放 `anon` 写入或放宽既有私有表。

**已有匿名版工程必做迁移检查**：让 TraeWork 先只读列出前端 Repository 的实际表名、每张表的 `GRANT`、`pg_policies` 中的 `roles/cmd/qual/with_check`，再设计版本化迁移。旧策略若只有 `TO anon`，即使表已经授予 `authenticated` INSERT/UPDATE，密码用户仍会被 RLS 拒绝。迁移后核验每张表的 SELECT、INSERT、UPDATE、DELETE 策略与登录用户的真实 UID；不要只看管理员 SQL 查询成功。已有演示行若归属字段为空，先明确归属或清理虚构数据，再启用用户归属策略。

## 第二步：接入网页

```text
继续 V2：保持 Canvas 页面与 V1 的 Repository 接口。V1 IndexedDB 模式独立保留；CloudBase 模式只在线读写演示用户的数据，不做 IndexedDB 双写或离线队列。先核对 Repository 实际读写的表名与 SQL 迁移表名一致。在云端模式显示最小登录表单（账号、密码、登录状态、退出），不做注册或账号切换。用 CloudBase Web SDK 的 signInWithPassword({ username, password }) 登录，检查 error 与返回的 session；重开页面用 getSession() 恢复会话，未登录时不读写 PG 或图片桶。凭据由我在页面手工输入，绝不写入代码或构建产物。请在两个独立浏览器会话用同一个演示用户实测创建→刷新读取→修改→删除→再次刷新，并检查错误密码、退出和断网失败时输入不会丢失。保存失败时显示可理解的真实原因和请求阶段，不要沿用 Canvas 原型里“存储空间受限或被拦截”的固定提示；不要向页面或日志输出密码、密钥或完整令牌。列出 VITE_DATA_MODE=cloudbase、EnvId 和 Publishable Key 的配置位置；管理密钥不可进入前端。
```

**预期结果**：浏览器 A、B 各登录同一演示用户；A 新增错题后 B 刷新能看到，B 修改或删除后 A 刷新能看到。未登录时只显示登录入口，错误密码有明确提示。断网时显示失败或重试提示，不能声称已同步。

## 第三步：准备静态发布

按[网页上线案例](09-网页上线案例.md)让 TraeWork 生成 Pages 工作流与 Vite `base` 路径，在容器中构建。此次可记录“公网未验证”，继续 V3。网页文件放 GitHub Pages，实时数据仍由 CloudBase 提供。

**过关检查**：保存真实错题后刷新仍存在，修改和删除也实际写入同一云端表；同一演示用户在两个浏览器双向同步题目、等级和图片；未登录访问被拒绝；错误密码、退出和断网路径可见；Pages 配置与构建通过。记录实际表名、`authenticated` 的四种 RLS 策略和脱敏的保存结果；仅有 `GRANT`、管理员读表成功或登录成功均不算通过。把证据写到 `docs/progress/V2.md`，不要记录密码，再进入[V3](06-V3-安卓.md)。
