# 7｜V4：给已有产品加 AI

你只需说“我要加 AI 能力”。固定调用链是：**已登录的网页或 APK → CloudBase Web SDK 的 `callFunction()` → CloudBase 云函数 → 硅基流动模型 API → 云函数校验结果 → 页面**。V2 创建的课程演示用户继续使用；模型由硅基流动提供。APK 不直接请求模型，也不保存模型 API Key 或演示用户密码。V1 的 Canvas 页面布局继续沿用。

| 任务 | CloudBase 云函数 | 课程默认模型与配置 | 预期输出 |
| --- | --- | --- | --- |
| 题图识别 | `vision-question` | 图文模型 `Qwen/Qwen3.8-27B`，环境变量 `CLOUDBASE_AI_MODEL` | 可编辑的题干、学科、年级草稿 |
| 错因诊断、分层引导、变式题、七天报告 | `learning-ai` | 文本模型 `deepseek-ai/DeepSeek-V4-Flash`，环境变量 `CLOUDBASE_TEXT_MODEL` | 经云函数检查后的结构化学习建议 |

课程默认固定为 `Qwen/Qwen3.8-27B` 和 `deepseek-ai/DeepSeek-V4-Flash`，Provider 为 `siliconflow`。TraeWork 直接用这两个 ID 配置对应云函数，并实测调用；若学员账号无法调用其中某个模型，报告准确错误和受影响步骤，再与教师确认替代模型。不要自行改用 CloudBase 自带模型。

1. 检查 V3 的网页和 APK 已用同一个课程演示用户登录同一 CloudBase 环境，并重新完成一题的创建、刷新读取、修改与删除。**预期结果**：两端共享虚构示例错题，保存链路真正通过；如果保存仍失败，返回 V2 检查实际表名、`authenticated` 的 GRANT/RLS 和用户归属字段，不能继续用 AI 识别成功代替保存验收。
2. 取出在[环境配置阶段](01-环境.md)用自己账号创建并保管的硅基流动 API Key；若当时尚未创建，现在去自己的控制台创建。由你在**自己的 CloudBase 云函数服务端环境变量**中填写 `SILICONFLOW_API_KEY`；不要发在聊天里，也不要放到 `.env.local` 的 `VITE_*`、GitHub、网页或 APK。**预期结果**：TraeWork 能确认变量已配置，但不会回显值；教师资料中没有可复制的 Key。
3. 让 TraeWork 检查 `usernamePassword` 登录方式、`getSession()` 和 `vision-question`、`learning-ai` 的**客户端调用权限**。先只读查看现有规则，再为这两个函数配置仅非匿名已登录用户可调用，其他函数不随之开放。规则可用 `{"*":{"invoke":false},"vision-question":{"invoke":"auth.loginType != 'ANONYMOUS' && auth != null"},"learning-ai":{"invoke":"auth.loginType != 'ANONYMOUS' && auth != null"}}` 表达；若已有其他函数规则，先合并，不能盲目覆盖。CloudBase PG 环境还须核对网关策略，并以真实会话验证。**预期结果**：演示用户登录后 `callFunction()` 能进入两个函数；未登录和匿名会话被拒绝。先用空参数调用 `vision-question`，若返回函数自身的“缺少图片数据”，说明权限层已通过且没有产生模型调用；若仍返回 `EXCEED_AUTHORITY`，先检查函数安全规则、网关权限和会话，不要立即换模型或 Key。限制函数频率及服务端每日调用量；默认账号本身不免除模型费用。
4. 发给 TraeWork：

```text
使用 knowstar-course Skill，我要 V4 AI。先检查我的 V3 网页和 APK 用同一个课程演示用户登录同一 CloudBase 环境，并只读检查 getSession() 与云函数客户端调用规则。vision-question 和 learning-ai 仅允许非匿名已登录用户调用，其他函数不随之开放；不要将账号密码写入代码。若 callFunction 报 EXCEED_AUTHORITY，先核对真实会话、函数安全规则和网关权限，再检查模型调用。固定调用链：前端只用 CloudBase Web SDK 的 callFunction() 调用 vision-question 和 learning-ai 两个云函数；云函数在服务端用 HTTPS 请求硅基流动的 OpenAI 兼容 chat/completions API。固定 Provider 为 siliconflow；vision-question 默认配置 CLOUDBASE_AI_MODEL=Qwen/Qwen3.8-27B，负责识别题图并生成可编辑草稿；learning-ai 默认配置 CLOUDBASE_TEXT_MODEL=deepseek-ai/DeepSeek-V4-Flash，负责错因诊断、分层引导、变式题和七天报告。云函数环境中设置 SILICONFLOW_BASE_URL、SILICONFLOW_API_KEY 和 CLOUDBASE_AI_PROVIDER=siliconflow；启用识图函数时还要设置 CLOUDBASE_AI_READY=true。告诉我在哪里安全填写 Key，不索取或回显它，也不放进 VITE_*、Git 或 APK。为两个函数配置服务端用量限制；先按默认模型实际调用，若账号无法调用，报告错误并等待教师确认替代模型。

按顺序实施并逐项给我可见结果：① 选图预览→调用 vision-question→可编辑识题草稿→我确认后保存；② 调用 learning-ai 完成可编辑错因诊断；③ 分层引导；④ 变式题验证；⑤ 七天复习报告。每一步检查云函数实际返回、失败时手工继续、网页与 APK 的结果一致。服务端校验模型 JSON；模型不能直接升星，只能在学生完成有效变式验证后触发既有升级规则。不要改变 V1 Canvas 页面设计，不让我选择模型服务商。
```

**TraeWork 应交付**：两个云函数及其环境变量清单、前端 `callFunction()` 调用点、服务端硅基流动请求与结构化校验、真实调用记录和失败回退记录。只报告 Key 是否已配置，不输出 Key 值。

| 小成果 | 你亲眼验收 |
| --- | --- |
| 识题草稿 | 上传题图后出现可修改的题干/学科等字段；你确认后才保存。 |
| 错因诊断 | 建议可编辑，错误建议可以不采纳。 |
| 分层引导 | 引导学生思考，不直接篡改原题和等级。 |
| 变式题验证 | 只有完成有效验证才按既有规则升级；重复点击不重复升级。 |
| 七天报告 | 报告来自共享演示学习记录；另一个设备也可看到。 |

**失败也要试**：暂时使模型调用超时或返回错误，检查原图和输入仍在，学生能手工录题；浏览器开发工具和 GitHub 代码中不能出现 API Key。密钥或额度问题先修复配置，再重新验收真实调用。默认模型不可用时，记录硅基流动返回的具体错误，不静默换模型。

**过关检查**：先证明演示用户会话与两个函数的客户端调用权限通过，未登录与匿名调用被拒绝；再完成至少一次真实 Qwen 识图、人工修改保存、一次真实 DeepSeek 诊断与变式验证、一次失败回退。网页和 APK 都通过 CloudBase 云函数取得结果，浏览器网络请求与 APK 中没有演示用户密码或硅基流动 Key；V1–V3 的核心流程仍通过。把脱敏截图、调用结果和未完成项写到 `docs/progress/V4.md`。
