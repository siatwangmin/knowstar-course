# 3｜先和 Gemini 想清楚，再写代码

在 Gemini 新建对话。以下每一轮**只发一段**，读完结果、回答它的问题，再发下一段。你的原始想法可以很短：“做一个学生用的错题怪兽卡片网页”。这一阶段只保存两个文件到 `knowstar-learning/docs/design/`：`PRD.md` 和 Gemini Canvas 导出的可运行 HTML（例如 `know-star.html`）。教师的参考文档和工程不给学员；不要求另写 spec 或原型交接文档。

| 轮次 | 发给 Gemini 的话 | 你应得到并检查 |
| --- | --- | --- |
| 1 访谈 | “我是零基础学员，想做一个学生用的错题怪兽卡片网页。先问我不超过 6 个最影响产品的选择题，每题解释两个选项的差异。现在不要写 PRD、代码或技术方案。” | 你能回答谁用、何时录题、怎样复习；Gemini 不擅自决定。 |
| 2 用户路径 | “根据我的回答，用一个学生周一录错题、周末复习的故事，列出从打开网页到完成复习的动作。标出失败和空数据时看到什么。只谈产品行为。” | 有“录题→复盘→升级→周末试炼”路径。 |
| 3 PRD 初稿 | “把已确认的内容写成 PRD 初稿：目标用户、问题、核心流程、V1 必做/V2 云端/V3 安卓/V4 AI 的边界、功能规则、失败提示和每项验收方法。未确认内容标为待定，不自行发明。给我可复制 Markdown。” | 将结果暂存为 `docs/design/PRD.md`；V1 不强迫你开云账号。 |
| 4 PRD 评审 | “只评审这份 PRD，不另写技术规格书。检查录题字段、学科、错因、LV1–LV3 升级条件、周末试炼选题、A4 打印、保存失败后的输入保留，以及每条必做需求是否能亲手验证。列出矛盾并问我决定；按我的回答修订同一个 PRD.md。V1 只做单页怪兽图鉴、添加弹窗和周末试炼，不做五 Tab。” | `PRD.md` 包含清楚的产品规则和可观察验收，没有第二份文档。 |
| 5 原型结构 | “现在进入 Canvas。依据我的 PRD.md，先用文字列出 V1 单页信息结构和每个操作的前后状态：学科胶囊、怪兽卡、翻面、添加弹窗、画板、错因胶囊、LV1–LV3、周末试炼 A4 打印。不要画五个底部 Tab。列出我必须亲自点击检查的操作。” | 页面结构符合单页产品，交互覆盖 PRD，不只是静态海报。 |
| 6 Canvas | “在 Gemini Canvas 中做一个可操作的 V1 原型。视觉使用暖奶油底色、Neo-Brutalism、3D 卡牌翻转、礼花和 Web Audio；行为遵守我的 PRD.md。提供空列表、保存失败、长题干、小屏幕状态。请让我实际点击录题、画图、翻卡、升级、打印；告诉我哪些只是模拟。” | Canvas 原型可点击；你亲手走一遍完整流程。 |
| 7 修订与导出 | “根据我刚才试用发现的问题，只修订 PRD.md 和当前 Canvas 原型。然后从 Canvas 导出完整、可运行的单文件 HTML；把布局、颜色、字号、状态、交互及所需的 CSS/字体依赖体现在 HTML 中。若使用 Tailwind CDN 或其他外部资源，请在 HTML 注释中标明，以便 TraeWork 在本地工程中正确实现。不要另写 spec、交接包或产品代码。” | `docs/design/PRD.md` 与导出的 HTML 均存在；直接打开 HTML 能操作。 |

**过关检查**：你能用自己的话说明“录一题后如何复习、何时升星、周末打印什么”；`PRD.md` 和实际 HTML 文件均存在；原型真实可操作。把这两个文件交给 TraeWork，进入[V1](04-V1-本地网页.md)。若不满意，继续在 Gemini 对话修改，不急着开发。
